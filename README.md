# Mリーグ 個人スコア集計（非公式）

**このページは非公式です。** 株式会社Mリーグ機構および各チームとは関係がありません。
個人が趣味で作ったもので、成績は [M.LEAGUE 公式サイトの成績表](https://m-league.jp/stats/)
から取っています。正確な情報は必ず公式でご確認ください。

👉 **https://ryogotamura2-ai.github.io/m-league-score/**

Mリーグの選手を4人ずつ2組に分けて、**合計スコアを比べる**ページ。
実在の10チームをまたいで組んだ「自分の編成」どうしを突き合わせる遊びのための道具で、
公式の順位とは関係ありません。

画面は3つ。

1. **2組の合計スコア** — 差と、どちらが上か
2. **個人スコアランキング** — 全40人。見出しを押すと並べ替わる
3. **カスタム編成** — 4人ずつ選び直して比べる

**毎朝7時（日本時間）に自動で新しくなります。** 見る側は何もしなくてよく、
リンクを開くだけです。

---

## どう動いているか

```
毎朝7時  GitHub Actions が起きる
   ↓
   公式サイトから成績を取る（届かなければ別の経路へ）
   ↓
   検算する（全選手のポイント合計が0になるか）
   ↓
   通ったらページに焼き込んで、このリポジトリに書き戻す
   ↓
   GitHub Pages が新しいページを配る
```

サーバーもデータベースも要りません。ページは外部の部品をひとつも読み込まない
単一のHTMLで、グラフも手書きです。

### 取得経路が3つある

環境によって、どこに接続できるかが違うため。上から順に試して、届いたものを使います。

| 経路 | 取りに行く先 | 数字の正確さ | 要るもの |
|---|---|---|---|
| `official` | m-league.jp | 公式そのもの | 公式への接続 |
| `db` | github.com | 正確（機械可読） | **非公式のデータ**（[konoui/m-league-game-db](https://github.com/konoui/m-league-game-db)） |
| `gemini` | Google の API | **モデルを通るので要検算** | `GEMINI_API_KEY` |

どの経路で取ったかは、ページの「出どころ」に必ず出ます。

### 壊れた数字が表に出ない仕組み

**麻雀は1試合の合計が必ず0になります。** だからリーグ全員のポイントを足すと0になる。
実データで確かめてあります。

| 対象 | 選手 | のべ試合 | 合計 |
|---|---|---|---|
| 2025-26 レギュラー | 40人 | 1200 | ±0.0 |
| 2025-26 セミファイナル | 24人 | 120 | ±0.0 |
| 2025-26 ファイナル | 16人 | 64 | ±0.0 |

**数字を1つ写し間違えれば、ここがずれます。** 検算に落ちたら書き出さないので、
**失敗した日は前の日の数字がそのまま残ります**（古い数字を出すほうが、
壊れた数字を出すよりましなので）。

## 中身

| ファイル | 役割 |
|---|---|
| `index.html` | ページ本体。外部の部品を読み込まない単一ファイル |
| `data/stats.json` | 成績。毎朝の自動更新が書き替える |
| `data/history.jsonl` | 更新のたびに1行。あとから推移を出すため |
| `scripts/fetch_stats.py` | 取得の入口。経路を選び、検算を通す |
| `scripts/validate.py` | 検算（ゼロサム・着順の辻褄・件数） |
| `scripts/gamedb.py` / `gemini_fetch.py` | 経路その2・その3 |
| `scripts/embed_stats.py` | `data/stats.json` を `index.html` に焼き込む |
| `run-selftest.js` | 画面の計算を、ブラウザ無しで検査する |
| `.github/workflows/update.yml` | 毎朝の自動更新 |

## 手元で動かす

```
pip install -r scripts/requirements.txt
python scripts/fetch_stats.py     # 成績を取る
python scripts/embed_stats.py     # ページに焼き込む
```

`index.html` をブラウザで開けば見られます（サーバー不要）。

### 検査

```
node run-selftest.js          # 画面の計算
python scripts/test_parse.py  # 公式ページの解析（実ページに対して）
python scripts/test_sources.py # 検算と各経路
```

通信もブラウザも要りません。

## 設計メモ（間違えやすい点）

### 公式の表は縦横が逆

選手が**列**、指標が**行**に並んでいます。素直に行で回すと、選手ではなく
「試合数・総局数・ポイント…」を選手名として読んでしまいます。

### 未出場の選手は 0 で埋まっている

`-` ではなく `0`。そのまま扱うと「0.0ポイントの選手」になり、**実際に打って
負けている選手より上に並びます。** 試合数0なら成績を「無い」ことにしています。

### 率の書き方が出どころで違う

公式は小数（`0.22` ＝ 22%）、配布データは百分率（`22.22`）。`%` の有無で判定して
単位をそろえています。

### 選手名に空白が入る

公式は姓と名の間に空白を入れます（`白鳥 翔`）。半角のことも全角のこともあるので、
揃えてから落としています。

### リーグ全体の個人ランキングは公式に無い

公式にあるのはチームごとの成績表10個だけです。**ランキングはこのページが自分で
並べ替えて作っています。**

### 取ってきた名前をページに埋め込んでいる

`<` `>` `&` はJSONの逃がし方で潰しています。以前 `</` だけを逃がしていた時期があり、
**取ってきた名前でコマンドを実行できる状態**になっていました（検査で塞いであります）。

## これは何ではないか

公式の順位表ではありません。ここで出している合計は、**公式のポイントを勝手に足しただけ**で、
Mリーグの順位・賞金・チーム成績とは何の関係もありません。
